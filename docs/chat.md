# 英文问候对话扩展

这是故事项目的独立小型 SFT 分支，目标为英文问候、感谢、自我介绍、简单请求和短交流，不是通用聊天模型。复用已训练的故事基座和原词表，不从随机参数开始，不覆盖故事/第四部分权重，不需要联网下载数据。

## 服务器运行

```bash
conda activate trackglimpse
cd ~/LLM
git pull --ff-only
python main.py stat=chat
```

一条命令自动准备数据、SFT、用基座与微调模型在相同测试集上生成真实回复、保存报告。默认500步，micro batch=4、grad_accum=2，学习率3e-5，最终权重保存在 `artifacts/chat/sft/final.pt`。不运行 DPO/RLVR 或前三部分实验，不应与其他 GPU 训练同时运行。

完成后启动或重启页面：

```bash
python main.py stat=web
```

沿用原来的6006端口 SSH 转发，在页面选择 **英文问候 SFT**，自动切到聊天模式。输入 `Hello!`、`How are you?`、`What is your name?` 等英文短句。对话来自实际权重推理，不通过词典匹配返回固定句子。微调是否成功要看服务器实际测试和生成内容，本地 CPU 微型模型测试只验证流程。

## 数据是什么

`resources/english_dialogue.json` 是项目内编写的合成种子模板，覆盖16类简单意图。每类训练问法与开发/测试问法分开，配合若干“用户介绍名字→追问名字”的短上下文任务自动展开。

- 训练400条，开发36条，测试36条。
- 检查完整 prompt 的大小写/空白归一化后互不重叠。
- 开发、测试仍与训练覆盖相同意图，不能宣称跨领域泛化；名字按split分开。
- 数据非大型公开聊天基准、非人工偏好标注，也不包含真实用户聊天记录。
- 这类小数据可能只学到有限回复套路，不能保证灵活问答。SFT本身不增加可靠的外部知识。

训练格式示例：

```text
User: Hello!
Assistant: Hello! It is nice to meet you. How is your day going?
```

仅 Assistant 当前回答与 EOS 参与 loss，用户消息和历史均掩码。使用已验证的 SFT 训练器，dropout=0、最终步权重、每100步保存可恢复断点；相同命令跳过已完成 SFT，继续生成评估。配置或数据变化拒绝混用旧输出，可更换 chat.output_dir。

## 页面如何保留上下文

聊天历史只保留在当前浏览器页面内存中，请求时带给本地服务器，不额外写入文件。服务器按完整问答轮次从最旧处裁剪，保证最新消息和回答窗口能放进模型的256 token上下文。不是长期记忆，可能只能带上一两轮；页面显示实际用了几轮。清空对话按钮会清掉页面历史。

聊天默认 greedy 解码以减少小模型随机跑题，不使用 seed 随机采样；最多80个新token。EOS或新的对话角色边界结束回答。若模型没有生成可见文本，会明确提示，不伪造一条成功回复，也不把占位文字作为历史。

用户输入限短英文；模型生成中的合法Unicode字符仍可作为历史保留。浏览器按需只缓存一个模型，切回故事模型仍使用原权重。

## 如何判断效果

`artifacts/chat/report.json` 保存基座和微调模型在同一测试集上的响应交叉熵、空回复比例、上下文名字匹配代理及所有真实输出。没有定义总体“聊天准确率”；名字追问只有两个测试名字，不能从0/50/100%推断通用记忆能力。

人工查看：是否回应了问候、有没有接着编故事、答非所问、重复、空回复、凭空声称能力或忽略上一轮。低 loss 不保证这些问题全部解决。报告会更新英文草稿的独立问候扩展说明，不替代第四部分的故事 SFT/DPO/RLVR 对照。

可选 `stat=chat_prepare` 只准备数据，`stat=chat_eval` 只评估已有问候权重；通常直接 stat=chat 即可。运行路径配置在 configs/chat/default.yaml。
